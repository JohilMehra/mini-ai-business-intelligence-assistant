# AI Business Intelligence Assistant

A lightweight, local sales analytics dashboard that lets business users ask questions about sales data in natural language. The application combines a React frontend, a FastAPI backend, SQLite database queries, and optional Gemini-powered question interpretation.

Revenue figures are calculated from eligible database records rather than generated by the LLM. A deterministic fallback supports common questions when Gemini is unavailable.

## 1. Features

- Ask natural-language questions about sales transactions.
- Calculate total net revenue.
- Identify the highest-revenue product and region.
- View monthly revenue trends.
- Compare revenue between two specified months.
- Validate sales data and track excluded records.
- Use Gemini for question interpretation, with a deterministic fallback.
- Return structured answers with supporting figures.
- Reject unsupported questions instead of inventing business answers.
- Run automated backend tests.

## 2. Architecture

```text
React + Vite
localhost:5173
       |
       | HTTP API requests
       v
FastAPI + Python
localhost:8000
       |
       +------> Gemini API (optional)
       |        Question interpretation
       |
       +------> Deterministic fallback
       |        Common question patterns
       |
       v
Allowlisted analytics functions
       |
       v
SQLite database
backend/data/sales.db
       ^
       |
Pandas CSV validation and import
       ^
       |
backend/data/sales.csv
```

**Request flow:** The frontend submits a question to FastAPI. The question interpreter identifies a supported intent. The backend validates the interpretation and calls the corresponding analytics function. The function queries eligible SQLite records and calculates the result. The API returns a structured response for the dashboard.

Gemini interprets questions; it does not calculate revenue or generate executable SQL.

## 6. Setup and Run

Run the backend and frontend in separate PowerShell terminals.

### Backend setup

From the project root:

```powershell
cd backend
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

If you have not created a local configuration file, copy the example:

```powershell
Copy-Item .env.example .env
```

**Important:** If `backend/.env` already exists and contains your Gemini API key, keep it. Do not overwrite it with the example file.

Start the backend:

```powershell
uvicorn main:app --reload
```

The API normally runs at `http://127.0.0.1:8000`.

### Windows virtual environment fallback

If virtual environment creation fails with an `ensurepip` error, the following alternative was used successfully with Python 3.13.2:

```powershell
py -m venv --without-pip .venv
py -m pip --python .\.venv\Scripts\python.exe install pip==24.3.1
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

If package downloads fail, check the configured package index and proxy settings. Keep TLS verification enabled.

### Frontend setup

Open a second PowerShell terminal:

```powershell
cd frontend
npm install
npm run dev
```

Open the local URL printed by Vite, normally:

`http://localhost:5173`

API documentation is available at:

`http://127.0.0.1:8000/docs`

To create the production frontend build:

```powershell
npm run build
```

The generated files are placed in `frontend/dist/`.

### Database initialization

On backend startup, the application validates and imports `backend/data/sales.csv` into `backend/data/sales.db`.

The import is designed to be repeat-safe. The optional `DATABASE_PATH` setting can override the database location; relative paths resolve from the backend directory.

## 7. Gemini API Configuration

1. Open [Google AI Studio API keys](https://aistudio.google.com/apikey).
2. Create or select an API key.
3. Configure the backend's `backend/.env` file:

```dotenv
GEMINI_API_KEY=your_actual_api_key
GEMINI_MODEL=gemini-3.5-flash-lite
```

Use a model currently available to your account. Check Google's [Gemini model documentation](https://ai.google.dev/gemini-api/docs/models) before changing the model setting.

The backend uses Google's official `google-genai` Python SDK.

### How Gemini is used

Gemini maps a natural-language question to a supported intent and, for month comparisons, two validated `YYYY-MM` values. The backend validates the interpretation and passes it to allowlisted analytics functions.

Gemini does not calculate financial figures or generate executable SQL.

When the API key is absent or the Gemini service fails, supported common question patterns can use the deterministic fallback. API responses identify the interpretation source as `gemini` or `fallback`.

**Security:** Keep the API key on the backend. Never put it in frontend files, commit `backend/.env`, or print it in logs.

## 8. API Endpoints

### `GET /api/health`

Returns service health and imported record counts.

### `GET /api/summary`

Returns dashboard summary information, including revenue, top product, top region, monthly trend, and record counts.

### `POST /api/question`

Accepts a natural-language question.

Example request:

```json
{
  "question": "Which product has the highest revenue?"
}
```

The response contains the answer and supporting information. Exact response fields are defined by the API implementation.

Unsupported questions return HTTP `422`.

## 9. Supported Business Questions

The application supports five main intents:

1. Total net revenue.
2. Highest-revenue product.
3. Monthly revenue trend.
4. Highest-revenue region.
5. Revenue change between two specified months.

For example:

> Compare revenue between 2026-01 and 2026-06.

Comparison questions should include two valid year-month values.

## 10. Data and Revenue Policy

The supplied dataset contains 51 transaction rows. The original file was found in the project root as `sales.csv.csv` and copied byte-for-byte to `backend/data/sales.csv`. The two files had matching SHA-256 hashes when copied.

The backend uses `backend/data/sales.csv` as its application input. The original file is retained unchanged.

### Dataset columns

- `Transaction_Id`
- `Order_date`
- `Product`
- `Category`
- `Region`
- `Sales_channel`
- `Quantity`
- `Unit_price`
- `Discount_amount`
- `Status`

### Revenue formula

```text
Net Revenue = (Quantity × Unit Price) − Discount Amount
```

### Validation rules

- Dates are parsed strictly as day-month-year (`DD-MM-YYYY`).
- Returned transactions are excluded from revenue calculations.
- Missing required values and invalid numeric values are excluded.
- Negative unit prices, quantities, discounts, and net revenue are excluded.
- A zero quantity is valid and produces zero revenue.
- Transaction IDs must be unique.
- Excluded records are retained with a reason for review.
- Repeated startup must not duplicate imported source records.
- All analytics functions operate only on eligible records.

The verified dataset contains 51 imported records, of which 49 are eligible for revenue calculations and two are excluded under the validation policy.

## 11. Testing

Run tests from the backend directory:

```powershell
python -m pytest -q
```

The test suite covers API behavior and validation cases. Tests use temporary CSV and SQLite files rather than the supplied dataset or development database.

The implementation was previously verified with **8 passing backend tests**. The frontend production build also completed successfully, and the dependency audit reported zero vulnerabilities at that time.

## 12. Development Notes

### AI tools used

OpenAI Codex assisted with code and documentation generation based on the implementation specification. Gemini is an optional runtime component for question interpretation; the deterministic fallback supports local use without a live Gemini request.

### Challenges addressed

- The original dataset had the unexpected filename `sales.csv.csv`.
- Missing and invalid data required a consistent exclusion policy.
- Database imports needed to be repeat-safe.
- Financial calculations needed to come from actual database records rather than LLM-generated numbers.
- Unsupported questions needed to be rejected safely.
- API credentials needed to remain server-side.

### Current limitations

- The question parser intentionally supports a small set of business intents.
- Gemini interpretation requires a valid API key, an available model, and internet access.
- The chart is a lightweight CSS-based bar chart.
- Currency display uses Indian Rupee (INR) formatting.
- Comparisons require specified year-month values.

### Possible future improvements

- Support configurable date ranges and richer question phrasing.
- Expand automated tests with more question variations and edge cases.
- Add currency metadata and configurable currency formatting.
- Improve chart interactions and accessibility.
- Add richer diagnostics without exposing credentials.

The backend process inherited proxy settings pointing to `127.0.0.1:9`, which refused the connection. When Gemini fails, the application can use deterministic fallback logic for supported questions. Do not describe Gemini as successfully tested until a response returns `source=gemini`.
